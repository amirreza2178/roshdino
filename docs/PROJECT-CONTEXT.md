# ROSHDINO — سند زمینهٔ اصلی

این فایل، متن کامل زمینه‌ای است که در ۱۰ مهر ۱۴۰۵ ثبت شد. بندهای «وضعیت فعلی» داخل سند، عکس لحظهٔ نوشتن همان سند هستند. کار انجام‌شدهٔ بعد از آن در `docs/CURRENT-STATUS.md` است و آن را به نقطهٔ صفر برنمی‌گردانیم.

0. دستور اصلی

تو از این لحظه وارد یک پروژه بلندمدت به نام ROSHDINO / رشدینو می‌شوی.

این پروژه فقط یک تمرین برنامه‌نویسی یا یک سایت نمونه‌کار نیست.

رشدینو قرار است یک کسب‌وکار دیجیتال واقعی، یک برند حرفه‌ای، یک سیستم جذب مشتری، و در آینده در صورت اعتبارسنجی بازار، یک مجموعه نرم‌افزاری و محصول‌محور باشد.

من می‌خواهم این پروژه را با تو از همین نقطه ادامه بدهم؛ بنابراین قبل از هر پاسخ، این سند را به‌عنوان Context اصلی پروژه در نظر بگیر.

مهم:
من نمی‌خواهم هر بار تصمیمات قبلی را دوباره توضیح بدهم.
نباید قوانین و معماری قبلی را نادیده بگیری.
نباید بدون دلیل معماری پروژه را عوض کنی.
نباید صرفاً برای زیاد کردن کد، پیچیدگی اضافه کنی.

تو باید مانند یک Senior Technical Partner + Software Architect + Product Advisor + Business/Market Advisor با من کار کنی.

سند اصلی پروژه نیز همین نقش را برای همکاری تعریف کرده است.

3. بازار اولیه

تمرکز اولیه: بازار ایران. به‌خصوص کسب‌وکارهای ایرانی، فعال در Instagram، با حضور دیجیتال ضعیف، سایت ضعیف یا بدون سایت، فرآیند دستی، مشکل جذب مشتری، یا نیاز به نرم‌افزار اختصاصی.

نیش‌های اولیه: پوشاک، بوتیک، فروشگاه تخصصی، طلا و جواهر، کلینیک زیبایی، سالن زیبایی، مدرس و آموزشگاه، املاک، شرکت‌های خدماتی، عمده‌فروشی و توزیع، رستوران و کافه، ساختمان و دکوراسیون، مراکز تعمیر و خدمات، فروشندگان دوره، کسب‌وکارهای آنلاین.

نباید از روز اول خود را به یک niche محدود کنیم. ابتدا مسئله‌های واقعی بازار پیدا می‌شوند.

4. خدمات اولیه

سه محور، بدون تکثیر به ده‌ها خدمت پراکنده:

A. طراحی و توسعه وب: سایت شرکتی، معرفی کسب‌وکار، فروشگاه، سایت خدماتی، رزرو، Landing Page، توسعه اختصاصی، UX/UI، Performance، SEO.
B. نرم‌افزار اختصاصی: اتوماسیون، مدیریت اطلاعات، CRM، فرآیند داخلی، سیستم اختصاصی، داشبورد، Workflow، سیستم مدیریتی.
C. راهکارهای رشد دیجیتال: UX، Conversion، SEO، Content، تحلیل حضور دیجیتال، Funnel، AI، اتوماسیون.

5. فلسفه سایت

سایت Portfolio Website نیست. سایت Customer Acquisition System است.

فانل: Attention → Clarity → Problem Recognition → Solution → Proof → Trust → Qualification → CTA → Lead → Conversation → Meeting → Proposal → Client → Project → Case Study → Next Client.

هر بخش باید حداقل یکی از این‌ها را انجام دهد: Attention، Clarity، Trust، Proof، Education، Qualification، Conversion. بخش فقط زیبا، باید توجیه شود.

6. اصل Conversion

هدف، کاهش اصطکاک تصمیم‌گیری است، نه تبدیل اجباری.

اصول: Cognitive Fluency، Progressive Disclosure، Social Proof، Choice Architecture، Commitment Ladder، Progressive Qualification، Clear CTA، Low Commitment CTA.

Hero باید در چند ثانیه بگوید رشدینو چیست، چه مشکلی حل می‌کند، چه می‌سازد، و قدم بعدی چیست.

7. طراحی برند

Style: Modern Editorial + Digital Precision.

پالت: Deep Ink #101820، Electric Lime #B7F36A، Warm Ivory #F3F1EB، Growth Green #416B45.

رنگ‌ها باید در طراحی واقعی از نظر UX سنجیده شوند و فقط به‌خاطر بودن در سند تا ابد قفل نمی‌شوند.

8. Mobile First

اولویت: Mobile → Tablet → Desktop. نسخهٔ موبایل، دسکتاپ کوچک‌شده نیست.

9. Breakpoint QA

320×568، 360×800، 375×768، 390×844، 768×1024، 1024+، 1366×768، 1440×900، 1920×1080. اولویت اصلی: 375×768 و 390×844.

10. معیار موبایل

نباید باشد: Horizontal Overflow، Text Clipping، CTA خارج از viewport، Grid فشرده، overlap، عنوان بیش از حد بزرگ، line-height بد فارسی، tap target کوچک، footer خراب، sticky CTA مزاحم، menu خراب، anchor زیر header، عنصر تزئینی روی محتوا.

11. Hero

ساختار فعلی حفظ می‌شود مگر دلیل Conversion قوی باشد: DIGITAL GROWTH STUDIO، تیتر کسب‌وکار، دو CTA، میکرو لینک مسئله، WEB / SOFTWARE / GROWTH، Growth System Visual. اصل: Short + Clear + Premium + Conversion-first.

12. Problem

کاربر خودش را در مسئله ببیند و Qualification اتفاق بیفتد.

13. Services

سه خدمت outcome-oriented. نه فهرست تکنولوژی. وب: سایت سریع و قابل توسعه. نرم‌افزار: مسئله → Workflow → System. رشد: UX + SEO + Content + Conversion + Automation + AI.

14. Process

DISCOVER → DESIGN → BUILD → GROW. هدف: کاهش اضطراب خرید. بعد از تحویل رها نمی‌شود.

15. Case Study

ساختار: Problem → Approach → Build → Result → Learning. کیس واقعی: Personal System Faraja. تکنولوژی واقعی: Laravel، PHP، MariaDB، Blade. عدد ساختگی ممنوع.

16. Trust

تکنولوژی ابزار حل مسئله است. اعتماد در کل سایت توزیع می‌شود: Process، Case Study، Copy، کیفیت فنی، Accessibility، Performance، شفافیت، پروژه واقعی.

17. FAQ

برای رفع objection واقعی، نه پر کردن صفحه.

18. Final CTA

اصطکاک کم و Progressive Disclosure. ترجیح آینده: یک انتخاب مسیر (سایت، نرم‌افزار، فروش، اتوماسیون، هنوز مطمئن نیستم) به‌علاوه راه ارتباطی و ارسال مسئله. فرم ۱۲ فیلدی ممنوع.

19. Sticky Mobile CTA

مزاحم محتوا و CTA اصلی نباشد. safe-area و tap target رعایت شود.

20. Accessibility

از اول معماری است: semantic HTML، keyboard، focus، skip link، aria-expanded، aria-controls، Escape، reduced motion، contrast، tap target، برچسب معنی‌دار، FAQ به‌صورت disclosure.

21. Navigation

واضح، سریع، قابل استفاده با کیبورد و لمس. منوی موبایل: aria، Escape، Focus، بستن بعد از رفتن به بخش.

22. SEO

People-first + Search-first + AI-readable. بدون keyword stuffing، صفحهٔ جعلی، doorway page، و محتوای بی‌ارزش.

23. SEO Foundation

lang=fa، dir=rtl، title، description، canonical، Open Graph، Twitter Card، heading معنایی، یک H1، structured data، sitemap، robots، لینک داخلی، Search Console. Schema فقط وقتی با محتوای واقعی صفحه یکی باشد.

24. JSON-LD

هرگز `@context` و `@type` خام در Blade. فقط `json_encode`. تست باید JSON را واقعاً parse کند.

25. Performance

CSS و JS کم، فونت کنترل‌شده، بدون ویدیو سنگین و اسکریپت شخص ثالث بی‌دلیل. هدف p75: LCP < 2.5s، INP < 200ms، CLS < 0.1.

26. استک ثبت‌شده در سند

Laravel 13، PHP 8.4.24، Composer 2.10.2، Node 26.7.0، npm 11.19.0، Vite 8.3.2، Git 2.55.0، Tailwind CSS 4، Vazirmatn. مسیر: `C:\Users\diplomat\roshdino`.

27. دیتابیس در متن اصلی سند

سند گفته بود تا وقتی Lead و Client و Project لازم نشده‌اند SQLite بماند. این شرط بعداً با وجود سرنخ و دستور صریح ساخت MariaDB به نام `roshdino` رد شد. جزئیات در وضعیت جاری است. برگرداندن به SQLite بدون دستور جدید ممنوع است.

28. معماری فنی

Laravel استاندارد، کنترلر سبک، Form Request، Eloquent. Service فقط با پیچیدگی واقعی کسب‌وکار. بدون Microservice، CQRS، و event-driven پیچیده از روز اول.

29. پکیج

قبل از نصب: نیاز واقعی، سازگاری Laravel 13، نگهداری، لایسنس، امنیت، و امکان حل بدون پکیج. اگر لازم نیست، نصب نمی‌شود.

30. Git

کامیت کوچک و معنی‌دار. هرگز `.env`، رمز، کلید و راز دیتابیس کامیت نمی‌شود.

31. GitHub

مخزن رشدینو از Personal System Faraja جدا است. تا وقتی وصل نشده، فرض push نمی‌شود.

32 تا 34. تست

تست بعد از تغییر مهم. اگر fail شد، اول رفتار محصول اصلاح می‌شود نه حذف assertion. JSON-LD باید decode شود. عدد «۸ تست و ۳۲ assertion» عکس قدیمی سند است؛ عدد زنده در وضعیت جاری و خروجی تست است.

35 تا 44. فرانت و QA

ساختار صفحهٔ اصلی حفظ می‌شود مگر دلیل قوی Conversion/UX. ظاهر: Premium Dark Editorial. موبایل باید composition واقعی داشته باشد، نه فشرده‌سازی دسکتاپ. اولویت عرض ۳۷۵ و ۳۹۰. اسکرین‌شات فقط برای اعتبارسنجی مهم، نه هر بخش. ادعای «موبایل عالی است» بدون دیدن نتیجه ممنوع است.

45 تا 55. اندازه‌گیری، بازار، تمایز

بعداً کلیک CTA، شروع و تکمیل تماس، FAQ، عمق اسکرول، و تبدیل موبایل در برابر دسکتاپ سنجیده می‌شود. معیار فروش فقط تعداد پیام نیست. SaaS فقط بعد از اعتبارسنجی. از رقبا الگو گرفته می‌شود، کپی نمی‌شود. تمایز: شفافیت، حل مسئله، مستندسازی، کیس واقعی، کیفیت، سرعت، دسترس‌پذیری، فرایند روشن، نتیجه‌محوری.

56 و 57. بیلد

هشدار fontaine در Vite دلیل نصب پکیج جدید نیست. حجم بیلد زنده را از خروجی واقعی می‌گیریم، نه از عدد قدیمی سند.

58 تا 65. صداقت و تعریف تمام‌شدن

نگو تست شد اگر اجرا نشده. Feature با نوشته‌شدن کد تمام نیست: پیاده‌سازی، بیلد، تست، واکنش‌گرا، دسترس‌پذیری، سئو، عملکرد، و آمادگی Git. امنیت: اعتبارسنجی، CSRF، Eloquent، رازها در env، مجوز، محدودیت درخواست، لاگ نکردن راز.

66. دادهٔ جعلی ممنوع

تستیمونیال، مشتری، متریک، درآمد، دفتر، جایزه، لوگو و نتیجهٔ کیس ساختگی ممنوع است.

67 و 68 و 69 و 70 و 71. اولویت محصول

اول وب‌سایت عمومی و موتور جذب. صفحهٔ خدمت، کیس‌استادی داستانی، دربارهٔ مبتنی بر روش کار، و تماس کم‌اصطکاک بعد از تثبیت صفحهٔ اصلی می‌آیند. CRM کامل روز اول ساخته نمی‌شود.

72. آیندهٔ مسیر فروش

Lead با وضعیت، منبع، مسئله، خدمت، ارزش، پیگیری، یادداشت، گفتگو، جلسه، پیشنهاد و مشتری. سپس Client، Project، Task، Delivery، Support، Case Study. ترتیب اجرایی در `docs/BACKEND-PLAN.md` است.

73 تا 78. همکاری

تصمیم معماری مهم با دلیل ثبت می‌شود. الگوی جدید با توضیح کوتاه و کاربرد در همین پروژه گفته می‌شود، بدون توقف کار. اگر تصمیم ضعیف باشد، مخالفت مستدل و گزینهٔ بهتر لازم است. هر لایهٔ اضافه باید دلیل داشته باشد. ساده، قابل نگهداری، قابل توسعه و تست‌شده حرفه‌ای است، نه پیچیده. شاهکار یعنی زیبا، سریع، دسترس‌پذیر، روشن، مفید، قابل اعتماد، قابل جستجو، تبدیل‌محور، قابل نگهداری و مقیاس‌پذیر.

79 تا 90. عکس وضعیت داخل سند

سند در آن لحظه اولویت را Mobile Premium QA گذاشته بود و گفته بود دیتابیس و CRM و بلاگ الان نیستند. بعد از آن، صفحهٔ اصلی برای ادامه کافی دانسته شد و ساخت مسیر فروش شروع شد. اولویت زنده را `docs/CURRENT-STATUS.md` تعیین می‌کند. کیفیت موبایل همچنان دروازهٔ قبل از هاست است، نه دستور بازگشت به فقط CSS.

فیلتر هر تصمیم جدید:

Conversion-first + Premium Frontend + SEO/Search/AI-ready + Accessibility + Performance + Quality + Mobile-first + Maintainability + Business Value.

اگر چیزی فقط قشنگ است و برای کاربر، کسب‌وکار یا کیفیت ارزش ندارد، اضافه نمی‌شود.

# سند جامع پروژه رشدینو

نقش همکاری: همکار فنی، معمار نرم‌افزار، توسعه‌دهنده ارشد، تحلیل‌گر بازار، مشاور محصول و کسب‌وکار. اجرا همراه با پیشنهاد بهتر، وقتی دلیل فنی یا تجاری دارد.

چشم‌انداز همان بندهای بالاست: برند قابل اعتماد در ایران، خدمات وب و نرم‌افزار و AI و Growth، رابطهٔ بلندمدت، تبدیل مسئلهٔ پرتکرار به محصول، درآمد تکرارشونده، کاهش وابستگی به زمان مؤسس. شروع کوچک و واقع‌بینانه است.

بازار اولیه ایران است، به‌خصوص کسب‌وکار اینستاگرامی با سایت یا فرایند ضعیف. جذب مشتری شخصی‌سازی‌شده است، نه پیام تبلیغاتی تکراری. موفقیت با نرخ پاسخ، مکالمه، جلسه، پیشنهاد و قرارداد سنجیده می‌شود، نه تعداد پیام.

هویت بصری: Modern Editorial + Digital Precision، موبایل‌اول، راست‌چین، تایپوگرافی فارسی، انیمیشن هدفمند، CTA روشن. پالت اولیه آزمایشی است نه قفل ابدی.

نسخهٔ اول سایت: خانه، خدمات، نمونه‌کار، درباره، تماس. وبلاگ و ابزار رایگان و پنل گسترده برای بعد است.

فناوری: Laravel 13، PHP، Blade، Tailwind، Git. اعتبارسنجی با Form Request. منطق تجاری وقتی پیچیده شد از HTTP جدا می‌شود. پکیج فقط بعد از بررسی نگهداری، سازگاری، لایسنس و امنیت. میکروسرویس و CQRS بدون نیاز واقعی ممنوع است.

قوانین همکاری که در این محیط معنی عملی دارند:

- خروجی قابل بررسی مهم‌تر از توضیح طولانی است.
- فایل‌ها مستقیم در مخزن ویرایش می‌شوند؛ چسباندن کل فایل داخل چت جایگزین ویرایش مخزن نیست.
- بین واقعیت، فرض و پیشنهاد فرق گذاشته می‌شود.
- تصمیم ضعیف تأیید نمی‌شود.
- قانون جدید قبل از ثابت شدن با امیررضا چک می‌شود.
- هر بستهٔ کاری به یک نتیجهٔ مشخص می‌رسد.

نقشه راه سند: فاز ۱ پایه و سایت اولیه، فاز ۲ برند و جذب، فاز ۳ عملیات فروش، فاز ۴ محصول بعد از اعتبارسنجی، فاز ۵ تیم فقط با توجیه اقتصادی. این‌ها زمان‌بندی قطعی نیستند.

فلسفه: کیفیت، اجرا، توسعه‌پذیری، بازارمحوری، پیشرفت مستمر. هدف، پایه‌های یک برند و کسب‌وکار به نام رشدینو است، نه فقط یک وب‌سایت.
